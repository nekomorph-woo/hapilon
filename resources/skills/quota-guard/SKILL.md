# 额度哨兵

额度撞墙的失败成本最高：任务半途而废、上下文丢失、重来做一遍。本技能让你在**专注工作时主动盯水位**，在撞墙前行动。

## 何时查（quota_check 工具）

- **长任务开工前**：预计多批次、多小时的任务，先查一次基线。
- **每完成一个批次后**：批次是天然的检查点，顺手一查（一次 API 调用，成本可忽略）。
- **异常迹象时**：模型调用连续失败、响应变慢、出现限流报错——先查额度再排查别的。
- 上次 verdict 是 `warn`：后续每个批次后必查。

工具输出每窗口一行（`5h 63% 重置 …（剩 2h 5m） WARN`）加一行机器可判的 `verdict: all_ok | warn=… | hot_rolling=… | hot_fixed=…`。阈值已内置于输出，按 verdict 行动，不用自己算。

## verdict 行动表

### `hot_rolling=…`（5h 滚动窗 ≥97%——会重置，值得等）

1. **落断点**：把当前任务状态写 `.hapilon/quota-guard/resume.md`——任务目标、已完成、下一步（具体到可执行）、恢复指令（「读本文件继续」）。目录不存在就创建。
2. **挂起到点续做**：用 background 工具跑 `sleep <到重置时刻的秒数>`（重置时刻在 quota_check 输出里）。background 命令退出会自动唤醒本会话——醒来第一件事：再查一次 quota_check 确认窗口已重置，然后读断点续做。
3. **告知用户**：哪个窗口、水位多少、预计几点重置、已挂起、断点在哪。一两句话即可。

### `hot_fixed=…`（周/月额度 ≥97%——等不起）

1. **暂停大批量任务**（研究、批量派发、马拉松审查）：继续做必撞墙，撞了还可能烧掉最后余额。
2. **告知用户原因**：周/月额度不会短期刷新，当前水位多少、预计何时重置，任务是暂停不是丢弃（断点同样落 `.hapilon/quota-guard/resume.md`）。
3. **等指示**：用户可能换 provider、改任务范围或手动决定继续。轻量单次问答不受影响，可以继续。

### `warn=…`（≥90%）

告知用户一句，然后把检查频率提到每批次必查。不中断工作。

### `all_ok`

不打扰任何人，继续干活。

## 边界

- 只盯当前模型 provider 的额度；多 provider 任务每个都查（工具可传 provider 参数）。
- 查询本身走一次配额接口调用，不是模型推理——不会烧 coding plan 额度。
- 挂起期间用户发了新消息：正常响应——断点续做与响应新指令不冲突，醒来时用户指令优先。
