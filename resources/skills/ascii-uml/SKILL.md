# ASCII UML 结构分析

## 目标

在对话里给出 ASCII 字符画的结构图加口头解读，读者不离开终端就看清结构与关系。

图的交付物是代码块，解读是正文。不产出图片文件，不产出网页。

## 时机

只收当前会话内的未完成工作，画图排最后：

- steering 中途插入本技能请求时：在跑的工作跑完立即画图，不重新排队，也不顺带收集后续新请求。
- 当轮请求里排在画图之前的其他请求：依次做完。
- 任务清单里本会话未完成的任务：做完再画。

历史遗留 TODO、其他会话的工作、用户没点名的仓库欠账一律不算。拿不准某项算不算，就不算。

## 图的选型

按读者的决策选主图，一张就够：

- 类图：什么属于什么，继承与组合。
- 时序图：谁调谁，消息按什么顺序走。
- 状态机：生命周期，状态怎么转移。
- 组件图：模块边界，依赖方向。
- 数据流：请求路径，pipeline。

拿不准就用组件图加一条主流程时序。分析范围不明时，先走 understand-this-codebase 建立心智模型，再画。

## 画法门槛

- 图放代码块里，等宽对齐。标签优先用真实标识符（类名、函数名、模块名），它们本来就是英文，对齐不会碎；中文判断放口头解读。
- 每行不超过 80 字符，终端、代码注释、commit message 里都放得下。
- 一图一主题。超过 15 个节点或要滚动两屏就分张，每张配自己的解读。
- 箭头语义全程统一，首图带一行图例。
- 节点与关系用项目既定词汇（`.hapilon/CONTEXT.md` 有就用），不造只在图里存在的抽象名词。
- 图后给两到四句口头解读：结构讲什么、关键决策或风险在哪、下一步看哪。不复述图上的连线。

## 记法

常用记法，保持全套一致即可，不必都用：

```
┌─────────┐      ┌─────────┐
│  Timer  │──>   │  Ticker │     依赖 / 调用
└─────────┘      └─────────┘
┌─────────┐
│ ReTimer │◁──              继承（箭头指向父类）
└─────────┘
idle ──start──> running ──stop──> idle          状态转移
req ──> parser ──> router ──> handler           时序 / 数据流
```

## 护栏

- 不用 mermaid、plantuml 语法冒充 ASCII，它们在终端里渲染不出来。
- 不画全景大图求全，分张比一张巨图可读。
- 不为图好看造不存在的层级或关系。
- 信息过密时先砍装饰（双线框、阴影），保标识符与箭头。
- 用户要网页可视化时转 answer-me-with-html，不硬画 ASCII。

## 与邻居的分工

- answer-me-with-html：网页级可视化解释归它；留在对话里、能复制进代码与文档的图归本技能。
- understand-this-codebase：理解归它，画图归本技能；范围不明先建模。
