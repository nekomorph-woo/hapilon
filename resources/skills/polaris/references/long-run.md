# 长任务编排

把一个大型交付（方案设计文档、批量改造、多腿调研落地）拆成决策块，放进一个自动循环跑完。人只出场两次：开工拍骨架，收尾看汇总。适用于明确说了要 AFK 或跨额度窗口续做的长任务。

## 人只出场两次

- **开工拍骨架**：产出文档大纲（或改造清单）+ 规则登记 + 每块的验收标准，交用户拍板。这次拍板断掉方向漂移的根，拍完即可 AFK。
- **收尾看汇总**：循环结束后给一份汇总——done 块清单、blocked 块与原因、等你拍板的待确认决定。

中途三类中断都不等人：

- 待确认的技术/细节决定：登记 [决策记录](decisions.md)，按当时最推荐的选项继续，不阻塞。
- 范围或已确认业务预期要变：标 blocked，跳下一块，汇总时集中给你。不硬写。
- 额度窗口将尽：quota-guard 落断点挂起，用 Agent 的 schedule（cron 或延时）在重置时刻自动唤起续派。

## 拆块

拆分单位是决策块，不是章节。每块自包含四要素：

- 输入：骨架 + 引用的规则 ID + 前置块产出
- 产出：可验收的实物——一节成稿、一份调研笔记、一组改造提交
- 验收：3–5 条文档版 Case。常用条目：结论有源引用、决策有备选对比、数字可复算、术语与 CONTEXT.md 对齐
- 状态：pending / running / done / blocked

粒度参考：一块 = 一次子代理执行能干完并自检的量，约 30–90 分钟、1–3 千字或一组小提交。大型交付 8–15 块。块间有依赖串行，没依赖同批并行派。不确定性大的主题先拆纯调研块（research 腿产笔记），写作块只消费已确认的笔记。

## 状态文件

状态真相只有一份，放工作目录的 `state.md`（任务清单型）：

```markdown
# <工作名> 长任务状态

- 骨架：<大纲/清单路径>，拍板依据：<日期与确认方式>
- 决策表：[decisions.md](../../polaris/decisions.md)
- 验收 Case：随骨架文件，逐块列 3–5 条

## 任务清单

| ID | 块 | 依赖 | 状态 | 产出 | 提交 |
|---|---|---|---|---|---|
| T-01 | 调研：认证方案对比 | — | done | .hapilon/research/auth.md | 1a2b3c4 |
| T-02 | 写作：方案总览 | T-01 | pending | docs/artifacts/plan.md §1 | — |

blocked 块在产出列注明原因。每块状态变化即落盘，不等整轮。
```

## 循环体

编排者（主会话）每轮做一件事：把下一个 ready 块送进闸门。

1. 读 `state.md`，挑一个依赖已满足、未 blocked 的 pending 块，标 running。
2. Agent 派 general-purpose 子代理执行，prompt 给全：块的四要素 + 骨架出处 + 现行决定。可并行的块同批多派。
3. 收到完成通知，跑验收：reviewer 子代理对这块的 Case 清单逐条判；「结论有源」这类带主观判断的条目用 3 票多数决，不为一次性任务建校准 judge。
4. 过闸：标 done，snap 提交，产出路径与提交号写回 `state.md`。
5. 不过闸：带驳回理由重派一次；再不过标 blocked，记原因，继续下一块。
6. 遇范围变化标 blocked；待确认决定登记决策表后继续。
7. 全部 done 或只剩 blocked 时停，出汇总。

编排者自己保持轻：每块结束把已消费的派发与验收过程 compress，真相在 `state.md` 与提交里，不在对话里。

## 安全阀

- **方向**：骨架拍板一次清掉关键决策；之后靠决策表的影响面列——某个决定翻案时，能算出哪些块受影响要重跑，损失可控。
- **质量**：闸门是 Case 全绿，不是「写完了」。不过闸不许标 done，宁可 blocked。
- **额度**：quota-guard 在水位 ≥97% 时落断点；schedule 在窗口重置时刻唤起续派。循环跨窗口不断在半截。

## 收尾汇总

固定四段：done 块清单（产出与提交号）、blocked 块与原因、等你拍板的待确认决定（各带当时的推荐与理由）、翻案影响面提示（哪个决定若改，哪些块要重跑）。
