# Backlog 记录

## 何时触发

- 代码中发现空目录、预留接口、未实现功能
- 用户说"先记下来""以后再做""这是预留"
- 上下文压缩前需要固化当前会话的技术决策

## 工作流程

1. **识别** —— 确认需要记录的内容类型：
   - 预留扩展：目录/接口已创建但无业务逻辑
   - 技术债：已知问题但当前不修复
   - 待实现：计划中的功能但不在当前 scope

2. **收集** —— 提取以下信息(会话上下文获取 + `/wok-kit:look` SKILL to find)：
   - 背景：为什么存在这个预留/技术债
   - 目的：未来解决什么问题
   - 当前状态：代码中实际是什么状态
   - 预期用途：将来做什么
   - 项目位置：代码中指向的具体文件和行号

3. **写入** —— 在 `_backlog/` 目录创建文件：
   - 文件名：`<kebab-case-topic>.md`
   - 内容：按下方模板填充

4. **确认** —— 告诉用户已记录，并给出文件路径

## 文件模板

```markdown
# <标题>

## 背景

<为什么存在这个技术债/预留>

## 目的

<未来解决什么问题>

## 描述

| 项目 | 内容 |
|------|------|
| 类型 | 预留扩展 / 技术债 / 待实现 |
| 当前状态 | <空目录 / 空函数 / 硬编码 / 其他> |
| 预期用途 | <将来做什么> |
| 创建时间 | <YYYY-MM-DD> |

## 参考引用

- <相关文档链接或 issue>

## 项目位置

- **创建**: `<file>:<line>` — `<描述>`
- **使用**: `<file>:<line>` — `<描述>`
```

## 示例

用户说："sessions 目录先留着，以后存会话历史"

→ 创建 `_backlog/sessions-directory-reserved.md`

## 检查清单

记录前确认：
- [ ] 文件名使用 kebab-case
- [ ] 包含背景、目的、描述、参考引用、项目位置五个块
- [ ] 项目位置精确到文件和行号
- [ ] 不记录已实现的完整功能
