# Teach Me

解答用户疑问——从项目代码库、项目文档和互联网中收集信息，帮助用户理解技术概念、代码逻辑或设计决策。

## 工作流程

### 1. 理解问题

- 提取核心疑问，判断问题类型：代码理解 / 概念解释 / 设计决策 / 数据查找 / 故障排查
- 若问题模糊不清（表述歧义、缺上下文、目标不明）→ 启动「追问协议」

### 2. 收集信息

按优先级依次检索，内层信息充分时不触发外层：

#### 2.1 项目代码库
- 搜索源码文件、配置、类型定义
- 追踪调用链、继承关系、数据流
- 查找注释和文档字符串

#### 2.2 项目文档
- CLAUDE.md、PRD、`_foresight.md`、`_CHANGELOG-alpha.md`
- `.claude/skills/` 下技能文档
- `_todo.md`、`_issue.md` 等记录

#### 2.3 互联网（仅在项目内信息不足时触发）
- 搜索官方文档、技术文章
- 标注来源 URL

### 3. 组织回答

- 用「人话」解释核心概念，非术语堆砌
- 标注信息来源（文件路径:行号 或 URL）
- 区分「事实」（已验证）、「推断」（基于代码分析）和「不确定」（标注 `需要确认`）

## 追问协议

问题满足以下任一条件时启动：

| 信号 | 示例 |
|------|------|
| 表述有歧义，多种解读 | "这个怎么改？"——改什么？改成什么样？ |
| 缺少关键上下文 | "那个接口报错了"——哪个接口？什么错误？ |
| 目标不明确 | "帮我看看这个模块"——看什么方面？ |

### 追问规则

1. **一次只问一个问题**，等待用户回答后再继续
2. **能从代码库查到的事实不要问用户**——先查再说
3. **每个问题附带推荐答案**，基于已有信息给出最佳猜测，供用户确认或纠正
4. **沿决策树逐分支追问**，上一回答决定下一问题方向
5. **达成共识后给最终回答**，不要边猜边答
