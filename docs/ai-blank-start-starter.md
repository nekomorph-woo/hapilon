# AI 复杂任务“脑子空白”启动器

这份文件解决一个非常具体的问题：

> 我知道有流程，但面对一个新活时脑子是空的。我不会写 Plan、Spec，也不知道第一句话怎么说。

答案是：**不要先写 Plan / Spec / Prompt。先让 AI 帮你生成这些中间产物。**

---

## 模式一：完全不知道怎么开始

```text
我现在还没有完整方案，也不知道最后应该做成什么。

这是我手头已经有的东西：
[文件 / 数据 / 旧报告 / 领导要求 / 截图 / 链接]

这是我目前模糊的感觉：
[哪怕只是抱怨也可以]

请不要直接做成品。
先像一个资深分析师一样，帮我：
1. 梳理已知事实；
2. 找出未知项；
3. 找出明显矛盾；
4. 猜测这个任务背后可能真正需要解决的 2～3 个问题；
5. 告诉我接下来最值得讨论的 3～5 个问题。

请把“事实”和“你的推测”明确分开。
```

---

## 模式二：有模糊目标，但不会写 Spec

```text
我的目标大概是：
[一句很粗糙的话]

我不想让你现在直接做最终成品。
请先把这个目标加工成一个“可讨论的问题框架”，包括：
- 用户是谁
- 用户要做什么判断
- 当前有哪些已知事实
- 哪些关键定义还没定
- 哪些地方存在多种方案
- 哪些地方一旦理解错，会导致最终交付物方向错误

最后给我一份“下一轮应该讨论什么”的清单。
```

---

## 模式三：已经讨论一轮，但不知道怎么变成 Plan

```text
基于我们刚才的讨论，请不要继续发散。

请把当前状态整理成一个 Execution Plan。
每个阶段写：
- 目标
- 输入
- 输出
- 本阶段允许模型自主决定什么
- 不允许自主决定什么
- 验收条件
- 进入下一阶段的 Gate

优先使用“小步验证”，不要一步做到最终成品。
```

---

## 模式四：有 Plan，但不会写 Spec

```text
现在把当前已经确认的内容整理成 Spec。

Spec 只记录：
- 已确认事实
- 已拍板规则
- 定义
- 边界
- 禁止事项
- 验收条件

未确认内容不要混进去，单独放在 Unknown / Proposal。

目标是：即使换一个模型，也不会重新发明业务规则。
```

---

## 模式五：有 Plan 和 Spec，但不会写启动 Prompt

```text
请基于当前 Plan 和 Spec，生成一个给新模型使用的 Start Prompt。

要求：
1. 明确首先要读哪些文件；
2. 明确谁是事实源、谁是方法论、谁是参考；
3. 明确当前只允许执行哪个阶段；
4. 明确本阶段输出文件；
5. 明确禁止提前做什么；
6. 明确完成后必须停止；
7. 明确自检问题。

Start Prompt 不重复整个 Spec，只负责正确启动工作流。
```

# 你需要记住的链路

```text
模糊想法
  ↓
Discovery
  ↓
Problem Frame
  ↓
Plan
  ↓
Definition / Decision
  ↓
Spec
  ↓
Start Prompt
  ↓
执行
```

Plan、Spec、Start Prompt 不是你必须凭空写出来的三篇作文。

它们是不同阶段自然产生的**中间产物**。

你真正需要掌握的不是“怎么写漂亮 Prompt”，而是：

> **现在应该让 AI 帮我生成哪一种中间产物。**

---

# 模型能力较弱时怎么办

不要优先把 Prompt 写得越来越长。

更有效的是：

1. 缩小单次任务；
2. 固定输入源；
3. 显式区分 Fact / Decision / Unknown / Proposal；
4. 一个阶段只允许一种主要角色；
5. 每阶段有输出文件；
6. 每阶段有 Gate；
7. 实现前先做 Wireframe；
8. 扩全量前先做极端 Prototype；
9. 结束时必须 Self-review。

一句话：

> **降低模型需要同时维持的隐含状态。**

模型越弱，越要把“脑子里的上下文”写到外部文件里。
