# 一页式 AI 复杂任务工作流

> 记忆口诀：**先倒出来，再搞明白；先定口径，再做设计；先做极端原型，再全量扩展；最后把经验写回系统。**

```text
┌───────────────────────────────────────────────────────────────┐
│ 0  DUMP｜先倒出来                                             │
│ “我还没想清楚。这是材料和零散想法，先梳理，不要直接做成品。”   │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 1  EXPLORE｜探索事实                                          │
│ 有什么？哪些可信？哪里冲突？哪里不知道？                      │
│ 输出：Fact / Source / Unknown                                 │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 2  FRAME｜定义问题                                            │
│ 谁在看？他要做什么判断？什么是噪音？做错会怎样误导？          │
│ 一句话：这是给 ___ 看，用来判断 ___ 的，不是用来 ___ 的。     │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 3  DEFINE｜钉死口径                                           │
│ Fact / Decision / Unknown / Proposal                          │
│ 每个核心词：是什么 / 不是什么 / 从哪来 / 能不能算             │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 4  DESIGN｜设计信息                                           │
│ 第一眼看什么？第二眼看什么？什么默认隐藏？                    │
│ 先 IA / Wireframe / Spec，不写代码                            │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 5  PROTOTYPE｜做极端原型                                      │
│ 一肥：最多 / 最复杂                                           │
│ 一瘦：最少 / 最异常                                           │
│ 只验证结构，不急着铺全量                                      │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 6  INSPECT｜反向验收                                          │
│ 不只问“能不能跑”，要问“它会不会误导我？”                      │
│ 查：0 / Unknown / 代理指标 / 默认状态 / 第一眼重点             │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 7  SCALE｜扩全量                                              │
│ 复制已验证模式，不重新发明系统                                │
│ 新情况先标 Unknown / Proposal，不偷偷改 Spec                   │
└───────────────────────────────┬───────────────────────────────┘
                                ↓
┌───────────────────────────────────────────────────────────────┐
│ 8  FREEZE｜固化经验                                           │
│ 最终 Spec + Decision Log + Unknown + Start Prompt             │
│ 目标：换模型 / 换会话也能恢复                                 │
└───────────────────────────────────────────────────────────────┘
```

## 每一步只记一个问题

| 阶段 | 只问这一句 |
|---|---|
| Dump | 我现在有什么？ |
| Explore | 客观事实是什么？ |
| Frame | 谁要用它做什么判断？ |
| Define | 我们说的这些词到底是什么意思？ |
| Design | 用户应该按什么顺序看到什么？ |
| Prototype | 最肥和最瘦案例都成立吗？ |
| Inspect | 它最可能怎样误导我？ |
| Scale | 我是在复制模式，还是偷偷改系统？ |
| Freeze | 下次换模型，还要不要重新解释？ |

## 脑子空白时的 6 句万能话术

```text
① 我现在还不知道最终该做成什么，先帮我梳理现状，不要直接做成品。
② 请区分：事实、我的猜测、你的推测、待确认项。
③ 谁会看这个东西？他看完真正要做什么判断？
④ 先把核心概念定义清楚，尤其告诉我“什么不算”。
⑤ 先做信息架构和两个极端样例，不要全量实现。
⑥ 现在切换成 Reviewer：这个东西最可能怎样误导我？
```

## 你与 AI 的分工

```text
你：目标 + 边界 + 拍板 + Gate + 验收
AI：搜索 + 整理 + 提炼 + 候选方案 + 实现 + 自检
```

## 最后一个提醒

**Discovery 文档 ≠ Delivery Spec**

“这个领域有什么”并不等于“这个用户应该看到什么”。

中间至少隔着：

```text
Frame → Define → Design
```

这三步通常才是复杂任务最需要人和 AI 共同思考的地方。
